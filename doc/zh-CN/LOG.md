## 缺陷

此日志记录网络主机上的工作.它不会取代上游项目的发布历史记录.

正在重启`codex-web.service`中断活动的浏览器 WebSocket 和 Codex 应用程序服务器子进程.考虑过滚动更新机制, 但没有实施.用户为每次重新启动选择了显式确认门.

## 限制

上游基线: `0dfdc10`

原因: fork 保留了上游 npm 和 Nix 包根及其提取然后修补工作流程.移动这些继承的条目会改变包路径并使上游更新复杂化.生成`scratch/`提取输出仍然被 Git 忽略, 并且仅由继承的构建工作流程使用.

更新边界: 此处仅保留记录基线中存在的根条目.新的第一方文件使用标准项目目录; 任何新继承的上游条目都需要审查和准确的库存更新.

文件和许可审查: 上游结帐声明 MIT`package.json`但不包含完整的许可文本.提取的桌面捆绑包和 npm 依赖项通知尚未经过完全审核.看[Third-party notices](THIRD_PARTY_NOTICES.md).这限制了有关重新分发提取或捆绑的工件的主张.

## 决策

|决定|原因|
| --- | --- |
|以静态浏览器预览方式打开本地网站资源, 首选同级浏览器`dist/index.html`. |用户请求仅供查看的预览.预览不会启动项目的后端.|
|在宠物设置页面上显示不可用消息.|该功能在此虚拟主机中不可用.|
|在“计算机使用”设置中显示相同的不可用状态, 并从“帮助”中删除其 Chrome 设置快捷方式.|继承的桌面集成无法通过此浏览器主机进行配置, 因此现有的控制页面给出了误导性的安装路径.|
|在此 Web 部署中的计划任务路由上显示不可用状态.|本地调度仅限于继承能力注册表中的Electron客户端, 目前可用的云列表失败; 否则, 该页面会通过失败的流程通告任务创建.这并不是说浏览器托管的调度原则上是不可能的.|
|在 Web UI 中隐藏桌面应用程序菜单.|它的仅限 Electron 的命令没有可用的浏览器操作.|
|将“关于项目”链接放在侧边栏问号菜单中.|桌面应用程序菜单未安装在浏览器中, 因此其左上角的“关于”条目不可见.可见的帮助菜单可以打开此分支, 而无需恢复文件, 编辑, 查看和帮助.|
|将本地文件上下文菜单应用程序目标替换为文件浏览器和下载操作.|桌面应用程序目标和本机保存对话框在浏览器中不起作用.远程主机操作保留其原始行为.|
|隐藏 Web UI 中的默认文件打开目标设置.|其桌面应用程序, 文件管理器和终端选项不控制浏览器文件操作.|
|单击时下载对话消息中的本地存档链接.|桌面文件打开操作没有这些文件的可用浏览器目标.|
|在存储库根保留继承的 npm, Nix 和补丁布局.|这可以保持上游更新和先提取后修补的构建兼容; 上面列出了确切的基线条目.|
|将部署移至`~/Desktop/apps/codex-web`, 节点位于该目录内.|然后, 启动器使用一种独立的部署路径; 之前的部署仍然需要回滚.|
|通过附件的现有删除回调从全屏预览中删除未发送的图像.|预览操作需与缩略图 X 匹配, 并且不得出现在已发送的图像上.|
|在全屏预览工具栏中使用文本标签进行删除.|Close 旁边的第二个 X 在视觉上令人困惑; 文本按钮保持了工具栏的风格并使操作变得清晰.|
|为登录页面提供一个居中的卡片, 其中包含帐户和密码字段以及真正的可信 IP 检查.|参考布局提高了层次结构; 次要操作检查现有服务器白名单并解释拒绝.|
|将登录页面保留为注销后的入口点, 包括受信任的 IP.|在登录页面明确选择可信IP访问; 单独的 IP 并不能创建会话.|
|在每次操作员发起的 Codex Web 重新启动或替换其运行进程之前, 都需要明确的用户确认.|重新启动会中断活动的对话和任务.先完成可逆的准备和检查, 描述具体的业务和预期的中断, 然后等待用户的肯定答复.空闲期或早期批准并不授权稍后重新启动.现有系统d`Restart=always`过程失败后的恢复与操作员发起的重新启动是分开的.|
|仅将滚动更新提案保留为历史设计.|与添加代理和重叠后端复杂性相比, 用户更喜欢显式确认门.没有实施代理或任务迁移.|
|从标题菜单和侧边栏行菜单在浏览器选项卡中打开本地聊天.|桌面新窗口 IPC 操作不会打开可用的浏览器窗口.两个菜单现在都使用浏览器的`/thread/<id>`路线, 侧边栏行在 Codex 模式下公开其菜单按钮.远程主机聊天被排除, 因为浏览器路由不会恢复其主机上下文.|
|在经过身份验证的浏览器选项卡中预览从对话链接的本地文件.|桌面文件编辑器选项卡可能无法在 Web 主机中呈现.预览会读取现有的经过身份验证的下载端点, 显示文本, 图像或 PDF, 并提供下载.远程主机链接保持其原始操作.|
|使用现有的 find-in-chat 命令将搜索按钮添加到对话标题.|客户端已经有一个带有匹配计数和上一个/下一个导航的查找栏; 标头缺少可见的入口点.|
|将 Web 应用程序的大小调整为移动设备和平板电脑上浏览器的视觉视口.|继承的`100vh`root 和 shell 的高度可能会超过动态浏览器栏或屏幕键盘留下的区域.视觉视口还报告其顶部偏移量, 该偏移量在键盘可见时可能会发生变化.|
|在此浏览器中将语音和普通 ChatGPT 聊天记录标为不可用.|当前通过 HTTP 部署的页面无法访问麦克风, 桌面语音功能也不会自动移植; 本地 Codex app-server 不提供普通 ChatGPT 账号聊天列表. 隐藏语音操作, 保留 Codex 对话记录.|
|从侧栏问号菜单打开本地更新日志页面.|用户需要查看此项目的更新记录; 页面从静态资源中读取对应语言的更新日志.|

## 变更日志

### 0.0.1(未发布; 工作更新于 2026-09-28)

#### 改变了

- 本地文件上下文菜单现在提供浏览器支持的文件操作.
- 侧边栏问号菜单现在链接到 GitHub 上的这个分支; 仅桌面应用程序菜单保持隐藏.对话搜索字段现在与现有菜单的白色表面和微妙阴影相匹配.
- 宠物, 键盘快捷键和计算机使用设置显示不可用状态; 侧边栏“帮助”菜单不再提供 Chrome 扩展程序设置.计划任务现在显示特定于部署的不可用状态, 而不是损坏的云列表和任务建议. Pet 配置文件操作, pet 斜线命令, 快捷方式帮助条目, 应用程序快捷方式绑定, 桌面应用程序菜单和过时的默认文件打开目标设置在 Web UI 中隐藏或禁用.
- 该项目保留了继承的上游构建布局, 同时将新的第一方结构和服务启动器移动到标准目录中.

- 网页中的语音操作已隐藏或标为不可用; ChatGPT 聊天记录区域说明此处无法同步网页和手机中的普通聊天. 侧栏帮助菜单现在可打开本地更新日志页面.
#### 固定的

- 本地网站资源卡打开静态浏览器预览, 而不是调用不可用的应用内浏览器.
- 对话消息中的本地存档链接会下载引用的文件, 而不是调用不可用的桌面应用程序.
- 未发送图像的全屏预览现在包括将其从草稿中删除的操作.
- 预览删除操作现在显示文本而不是 X, 并且登录页面使用重新设计的帐户/密码表单以及有效的可信 IP 检查.
- 聊天菜单的新窗口操作会打开一个浏览器选项卡, Codex 侧边栏聊天行会显示相同的菜单.
- 对话文件链接会打开带有下载按钮的浏览器预览, 而不是无法呈现的选项卡.
- 对话标题现在提供一个搜索按钮, 可打开现有的查找栏.
- 现在, 当浏览器栏, 旋转或键盘更改可用高度时, 移动设备和平板电脑布局将遵循可见视口.
